# 2026-11-18

## 64×64 HUB75 点阵显示数字 "3"（STM32F407VET6 梁山派/天空星）

在 `E:\VScode\新型装甲板` 根目录建了一个完整可编译工程：

- **硬件澄清**：用户贴的图是 RGB-Matrix-P2-64x64（HUB75，1/32 扫描，A~E），不是 OLED。
  HUB75 无"颜色选择脚"，红蓝是 R1/R2 与 B1/B2 独立数据通道 —— 已在 README 第 0 节说明。
- **引脚方案**（避开板载 LED PB2 / KEY PA0 / USB PA11-12 / SWD PA13-14 / SPI Flash PB10·PC2·PC3 / SDIO PC8-12·PD2-3 / 晶振）：
  - 数据+控制全在 GPIOB（一次 BSRR 写 9 位，是刷新率关键）：
    R1=PB0, G1=PB1, B1=PB11, R2=PB12, G2=PB13, B2=PB14, CLK=PB15, LAT=PB8, OE=PB9
  - 行选在 GPIOD：A=PD8, B=PD9, C=PD10, D=PD11, E=PD12
- **架构**：零依赖（自写 stm32f407_regs.h），4bit BCM 调光，64×64 RGB444 帧缓冲 + 位平面
  (32×4×64)，DWT 做 µs 延时，无中断。实测约 170Hz 刷新，text 3384B。
- **关键坑**：HUB75 移位寄存器先入后出，必须从第 63 列往第 0 列送，否则整屏左右镜像（3 变 Ɛ）。
  已在 `hub75_render()` 里反转，`HUB75_FLIP_X/Y` 可在软件里翻转。
- **字形**：不用点阵字模，6 段三次贝塞尔中心线 + 距离场抗锯齿，包围盒自适应映射到 0~64 → 天然满屏。
  `tools/glyph_proto.py` 是先看效果的 Python 版，`tools/host_preview.c` 可在 PC 上跑同一份 C 导出 PNG。
- **构建**：Makefile（GCC）+ `.vscode/tasks.json`（已指向 STM32CubeIDE 自带 gcc/make，shell 用 Git Bash）。
  Keil 只给了启动文件 + .sct，README 里写了 5 步建工程（没给 .uvprojx，避免版本不兼容打不开）。
- 本机验证：arm-none-eabi-gcc 14.3 编译链接通过；预览图用 Edge headless 截图核对 SVG 排版。

## 改版：整体换到 STM32F103C8T6（蓝板），F407 版已被替换

用户要求"换一下，使用 STM32F103C8T6"，工程按 C8T6 重写，F407 专用文件已删除
（startup / .ld / stm32f407_regs.h / gfx.* / 浮点字形 / host_preview）。

- **引脚（全新）**：数据+时序 PA0~PA8 连号（R1=PA0 G1=PA1 B1=PA2 R2=PA3 G2=PA4 B2=PA5
  CLK=PA6 LAT=PA7 OE=PA8），行选 PB5~PB9 = A~E（连号，写地址只需 a<<5）。
  避开 PC13(LED)/PA13-14(SWD)/PA11-12(USB)/PA9-10(USART1)/PA15·PB3·PB4(JTAG)/PB2(BOOT1)。
- **20KB SRAM 的取舍**：不做帧缓冲，`s_plane[32][4][64]` 8KB 直接画；字形改成
  `inc/glyph3_data.h` 2KB 4bit 字模（`tools/gen_glyph.py` 生成）。总 RAM 8.7KB/20KB。
- **无 FPU**：去掉全部浮点与 sqrtf，`-mcpu=cortex-m3`，不链 libm。
- **F1 特有坑**：GPIO 是 CRL/CRH 每脚 4 位（不是 F4 的 MODER）；APB1 必须 ÷2（36MHz 上限）；
  延时改用 SysTick（DWT 在 CS32/CH32 等兼容片上不一定可靠）。
- **实测**：text 3920 / data 4 / bss 11012，bin 3924 字节，0 warning；栈顶 0x20005000；
  刷新约 100Hz（BCM 基准 16µs），像素时钟 ~4MHz。
- 字模表与 Python 计算结果交叉验证：总亮度 25800、实心像素 1724，两边一致。

## 用户反馈"运行不了" → 定位到两个问题

1. **F5 报 `makeDebugType ... cmake 调试类型要求定义 cmake 命令`**：工程是 Makefile 的，
   没有 CMakeLists.txt；VSCode 装了 CMake Tools，无 launch.json 时会用它自动生成的
   CMake 调试配置。已补 `.vscode/launch.json`（cortex-debug + ST-LINK_gdbserver）。
2. **更要紧的：ST-Link 读不到芯片**。实测 `STM32_Programmer_CLI -c port=SWD mode=normal`
   → `ST-LINK FW V2J48S7 / Voltage 3.28V / Unable to get core ID / No STM32 target found`。
   普通模式、under-reset、800kHz 都试过，同样结果 → SWD 物理链路问题（DIO/CLK 没通或接反），
   不是代码问题。已在 README 4.2 与排错表写明判断方法。
- tasks.json 的 PATH 里补了 STM32CubeProgrammer 的 bin（make flash 要用 STM32_Programmer_CLI，v2.23.0）。
- 环境事实：CubeIDE 2.1.1 自带 openocd 0.12 但**不带 scripts**，ST 的 st_scripts 与新版 openocd
  不兼容（hla newtap 已废弃报错），所以调试走 ST-LINK_gdbserver，不要用 openocd。

## 改建为 CMake 工程（用户要求）

- 删除 Makefile，改为 `CMakeLists.txt` + `CMakePresets.json` + `cmake/gcc-arm-none-eabi.cmake`。
  生成器定为 **Ninja**（cmake 3.30 + ninja 1.11 都随 CubeIDE 装在
  `com.st.stm32cube.ide.mcu.externaltools.{cmake,ninja}.win32_*`）。
  产物 `build/matrix3.elf/.hex/.bin/.map`，target 名 matrix3，SUFFIX 强制 .elf。
- **重大坑：CMake 在 Windows 上不支持中文路径**。工作区 `E:\VScode\新型装甲板` 下
  `cmake --preset` 直接崩（exit 0xC0000409，preset 打印的路径已乱码 `鏂板瀷瑁呯敳鏉`）。
  同工程复制到 C:\temp 立刻通过 → 确定是路径问题。
  解法：建了目录联接 `E:\VScode\m3 -> E:\VScode\新型装甲板`，
  **以后用 VSCode 打开 E:\VScode\m3**。已在 README 4.5 写清。
- 另一个坑：CubeIDE 自带的 make.exe 走 Makefiles 生成器时会在最后抛
  `make (e=87): 参数错误`（cmake_progress_start 的 CreateProcessW 失败），
  产物虽然生成了但退出码=2。换 Ninja 后 exit 0，干净。
- 工具链文件必须加 `-specs=nosys.specs`（CMAKE_EXE_LINKER_FLAGS_INIT），
  否则 CMake 探测 ABI 时链接会报 `undefined reference to _exit/_sbrk`。
- tasks.json 不写 `&&`（Win 自带 PS 5.1 不支持），改成 dependsOn 复合任务；
  launch.json 的 preLaunchTask 指向 "build" 复合任务，仍然有效。
- 实测：FLASH 3780 B (5.77%)，RAM 11016 B (53.79%)，text 3776 / data 4 / bss 11012；
  bin 头 `00 50 00 20 75 06 00 08`（栈顶 0x20005000 + 复位向量）核对无误。

  package.json 完整、dist/debugadapter.js 在、engines ^1.69 满足、extensions.json 有条目、

  69047191fc / c4453f8ea4 两个 app 副本，根目录没有 resources，是更新后残留结构）。
  → 判定为扩展没被当前窗口加载（禁用 / 未重载 / 安装态异常），给用户四步：点弹窗安装 →
  启用 → Reload Window → Show Running Extensions 验证。
- ST 扩展的 `stlinkgdbtarget` 没有公开 configurationAttributes，要靠它自己的
  project manager 生成 .launch，手写不现实 → 坚持用 cortex-debug。
- **构建失败的真正原因**：用户仍在中文目录 `E:\VScode\新型装甲板` 里按 F5

## 【重要】SWD 连不上的真正原因：stlinkserver.exe 占用探针

- 用户反馈"Keil 能识别芯片并下载成功，VSCode 不行" → 说明硬件全好，是软件栈问题。
- 用 PowerShell 查进程发现 `stlinkserver`（PID 1800，19:43 启动，正是 F5 失败那次残留）。
  **kill 掉之后立刻连上**：`Device ID 0x410 / STM32F103 Medium-density / NVM 128KB / Cortex-M3`。
- 结论：`stlinkserver.exe` 是 ST 工具链的探针独占锁，Keil 用自己的 DLL 不受影响；
  CubeProgrammer / ST-LINK_gdbserver 会被它挡住，症状正是"电压 3.28V 有、core ID 读不到"。
  **以后遇到这个症状先杀 stlinkserver，不要去动杜邦线。**
- 已固化进工程：tasks 增加 `release ST-Link`（taskkill /F /IM stlinkserver.exe，带 exit 0），
  `flash` 与 `debug-prep`（launch.json 的 preLaunchTask）都会先执行它。
- 实机烧录已验证：`STM32_Programmer_CLI -c port=SWD -w build/matrix3.elf -rst` → 0.26s 完成，
  Erase sectors [0 3]，Software reset 执行。
- 顺手发现：这颗芯片实际 **NVM 128KB**（不是标称 C8T6 的 64KB），大概率是 CS32F103C8 之类的
  128K 版本。链接脚本按 64K 写，安全且够用。

## 用户反馈"还是下不进去 / 屏不亮"

- 用 `STM32_Programmer_CLI -u 0x08000000 32 dump.bin` 读回芯片内容，与 matrix3.bin
  **前 32 字节逐字节完全一致**（00 50 00 20 75 06 00 08 bd 06 ...）→ 固件确实在片内且已复位运行。
  注意：`-u` 的参数顺序是 `-u <地址> <长度> <文件>`，写反会报 "missing some arguments"。
- 结论：用户按的是 F5（调试）而不是 flash 任务；F5 走 ST-LINK_gdbserver，链路上更容易被占用。
- **给 main.c 加了 PC13 心跳灯**（HEARTBEAT_LED 宏，默认 1）：蓝板 PC13 低电平点亮，
  CRH[23:20] 配 2MHz 推挽，主循环每 50 帧翻转一次（约 1Hz）。
  用途：屏不亮时先看灯 —— 闪=CPU 活着，问题在屏接线；不亮=程序没跑。
- tasks.json 的 shell 固定成 powershell.exe（用户默认就是 PS），
  release ST-Link 改成 `taskkill /F /IM stlinkserver.exe 2>$null; exit 0`（PS 语法，必返回 0）。

## 2026-11-19 换回 F407（天猛星）—— 用户实际用的是 F407，不是 F103

- 用户提供原理图：核心板 2×40 排针 **按端口整组排列**，左边 H1 第 13~28 脚是：
  PE7~PE15（13~22，2×5）+ PB10~PB15（23~28）。
- 新引脚方案（14 根全在 H1 13~28 脚，飞线一把拉完）：
  **PE7= R1, PE8=G1, PE9=B1, PE10=R2, PE11=G2, PE12=B2,
    PE13=CLK, PE14=LAT, PE15=OE, PB10=A, PB11=B, PB12=C, PB13=D, PB14=E**
  数据+时序全在 GPIOE 且位号连续；行选在 GPIOB 位号连续（a<<10）。
  心跳灯 PB2（板载 LED，高电平点亮），不占这 14 根。
- 移植要点：GPIO 改回 MODER/OSPEEDR/OTYPER/PUPDR（每脚 2 位）；时钟 168MHz；
  AHB1ENR 使能 GPIOE(bit4)+GPIOB(bit1)；链接脚本 512K/128K；启动文件 82 中断；
  CMake `-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard`。
  ⚠️ 改启动文件名后必须同步改 CMakeLists 的源文件列表，否则 add_executable 报错。
  ⚠️ 删旧芯片头文件时记得改所有 #include。
- 实测：FLASH 1628B / RAM 17424B；烧录校验通过。
  芯片实际读到 **Device ID 0x413、NVM 1MB** → 是 F407VGT6 高配版，不是 VET6。
- 文档/接线图（docs/wiring.svg）已同步为 PE7~PE15 + PB10~PB14。
