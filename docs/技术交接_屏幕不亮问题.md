# HUB75 64×64 点阵驱动 —— 技术交接与故障分析

> 本文是给第三方（人或 AI）独立分析的完整背景材料。
> 不需要前情提要我，所有事实、参数、代码、现象都在这里。
> 目标：解释「为什么屏只显示一小块乱码，而且颜色不随固件内容变化」。

---

## 一、硬件

### 1.1 主控

| 项目 | 参数 |
|---|---|
| 型号 | STM32F103C8T6（最常见的那种蓝色最小系统板） |
| 内核 | Cortex-M3 @ 72MHz，**无 FPU** |
| 逻辑电平 | 3.3V |
| 封装 | LQFP48，可用 IO 只有 37 个（PA0~PA15 / PB0~PB15 / PC13~PC15） |
| 实际芯片 | CubeProgrammer 报 `Device ID 0x410`、`NVM size 128 KB`，说明是 128KB 版本（标称 C8T6 应为 64KB），大概率是兼容片 |

**板载已占用、不能用的引脚**：PC13（板载 LED，低电平点亮）、PA13/PA14（SWD）、PA11/PA12（USB）、PA9/PA10（USART1）、PA15/PB3/PB4（默认 JTAG）、PB2（BOOT1 有 10k 下拉）。

### 1.2 显示屏

| 项目 | 参数 |
|---|---|
| 型号 | Waveshare RGB-Matrix-P2-64x64（P2.5 间距），或 -B 版本 |
| 分辨率 | 64 × 64 |
| 接口 | HUB75（16P IDC），接口定义里**带 E 行选**，即所谓 HUB75E |
| 扫描方式 | 官方规格书写 **1/32 scan** |
| 供电 | 屏背面单独电源座，5V / 3A（**16P 排线里没有电源线**） |
| 缓冲器 | 板上 74HC245，VCC=5V |

**HUB75E 16P 引脚（标准）**

| 脚 | 信号 | 脚 | 信号 |
|---|---|---|---|
| 1 | R1 | 9 | A |
| 2 | G1 | 10 | B |
| 3 | B1 | 11 | C |
| 4 | GND | 12 | D |
| 5 | R2 | 13 | CLK |
| 6 | G2 | 14 | LAT / STB |
| 7 | B2 | 15 | OE（低有效） |
| 8 | **E** | 16 | GND |

⚠️ 注意：老式不带 E 的 HUB75 是 4/8/16 三个地；这块屏第 8 脚是 E。

### 1.3 当前接线

| 屏丝印 | 排线脚 | MCU | 备注 |
|---|---|---|---|
| R1 | 1 | PA0 | |
| G1 | 2 | PA1 | |
| B1 | 3 | PA2 | |
| R2 | 5 | PA3 | |
| G2 | 6 | PA4 | |
| B2 | 7 | PA5 | |
| E | 8 | PB9 | |
| A | 9 | PB5 | |
| B | 10 | PB6 | |
| C | 11 | PB7 | |
| D | 12 | PB8 | |
| CLK | 13 | PA6 | |
| LAT/STB | 14 | PA7 | |
| OE | 15 | PA8 | |

设计意图：PA0~PA5 正好对应 6 个数据位，可以一次 BSRR 写全部；CLK=PA6、LAT=PA7、OE=PA8 紧随其后，同端口。地址 PB5~PB9 连号，写地址只需 `a << 5`。

### 1.4 供电实测

数控电源设定 5V / 3A，实际输出电流 **0.14 ~ 0.16A**。
（64×64 全白时这类屏正常在 1~3A，显示一个字符约 0.3~1A。0.15A 基本等于"驱动芯片通电、LED 几乎不导通"。）

## 二、软件架构

零第三方库，直接操作寄存器（自带 `stm32f103_regs.h`）。**全工程无中断**。

### 2.1 时钟与延时

- HSE 8MHz → PLL ×9 → 72MHz；APB1 ÷2（36MHz）、APB2 ÷1；Flash 2 等待周期 + 预取
- 微秒延时用 **SysTick 单次计时**（不用 DWT，因为兼容片 DWT 行为不一定一致）

### 2.2 显存结构（无帧缓冲）

F103C8T6 只有 20KB SRAM，所以**不做帧缓冲，直接画进位平面**：

```c
static uint8_t s_plane[32][4][64];   /* 8KB */
```

- 第一维：行地址 a = 0~31
- 第二维：位平面 b = 0~3（BCM 权重 1/2/4/8）
- 第三维：列，**但存的是"移位次序"**，不是屏幕列号
- 每个字节的 6 个 bit 对应屏的 6 根数据线：

```
bit0 = R1   bit1 = G1   bit2 = B1   bit3 = R2   bit4 = G2   bit5 = B2
```

写像素时（`hub75_set_pixel`）：

```c
int col = HUB75_WIDTH - 1 - x;      /* HUB75 移位寄存器先入后出，第63列先送 */
uint8_t base = (y < 32) ? 0 : 3;    /* 上半屏 bit0~2，下半屏 bit3~5 */
uint8_t row  = y & 31;
for (k = 0; k < 4; k++) {
    /* 按 r/g/b 的第 k 位，置位 s_plane[row][k][col] 的对应 bit */
}
```

### 2.3 扫描时序（核心）

每个行地址做 4 个位平面，每位平面一次完整移位 + 锁存 + 点亮：

```c
void hub75_scan_frame(void)
{
    for (a = 0; a < 32; a++) {
        set_addr(a);                          /* PB5~PB9 = a */
        for (b = 0; b < 4; b++) {
            HUB_GPIO->BSRR = (1 << PIN_OE);           /* OE 拉高 = 关闭显示 */
            shift_line(s_plane[a][b]);                /* 64 个 CLK */
            latch();                                  /* LAT 高脉冲 */
            HUB_GPIO->BSRR = (1 << (PIN_OE + 16));    /* OE 拉低 = 点亮 */
            board_delay_us((1 << b) * 16);            /* 16/32/64/128 µs */
            HUB_GPIO->BSRR = (1 << PIN_OE);           /* 熄灭，换下一位平面 */
        }
    }
}
```

移位内层（用了预计算的 BSRR 查找表，一次写更新 9 个引脚）：

```c
for (i = 0; i < 64; i++) {
    uint32_t v = px[i];
    HUB_GPIO->BSRR = s_lut_lo[v];   /* 数据 + CLK=0 + LAT=0 + OE=1(关) */
    NOP × 8
    HUB_GPIO->BSRR = s_lut_hi[v];   /* 数据 + CLK=1 上升沿 */
    NOP × 8
}
HUB_GPIO->BSRR = (1 << (PIN_CLK + 16));   /* CLK 回低 */
```

```c
static inline void latch(void)
{
    NOP × 8;                                    /* 等 CLK 振铃衰减（后加的） */
    HUB_GPIO->BSRR = (1 << PIN_LAT);
    NOP × 4;                                    /* 约 55ns 脉冲 */
    HUB_GPIO->BSRR = (1 << (PIN_LAT + 16));
}

static inline void set_addr(uint32_t a)
{
    GPIOB->BSRR = ((a & 0x1F) << 5) | (((~a) & 0x1F) << 21);
}
```

### 2.4 当前参数

| 宏 | 值 | 含义 |
|---|---|---|
| `HUB75_BCM_BASE_US` | 16 | BCM 最小位平面的点亮时间 |
| `HUB75_CLK_NOP` | **8** | CLK 边沿前后插入的空指令数（原为 2，为排除串扰放大到 8） |
| `HUB75_FLIP_X` / `FLIP_Y` | 0 / 0 | 软件翻转 |
| 帧时间 | ≈ 10.7ms | 约 94Hz 刷新 |
| 单行时间 | ≈ 333µs | 4×(移位 23µs + 锁存) + 240µs 点亮 |

### 2.5 调试辅助

- **PC13 心跳灯**：主循环每 50 帧翻转一次（≈1Hz）。已确认在闪 → 主循环在跑。
- 固件里有三种测试模式（宏 `WIRING_TEST`）：
  - `0` = 显示数字 "3"（上红下蓝）
  - `1` = 四色方块：左上白 / 右上红 / 左下绿 / 右下蓝
  - `2` = 单通道轮播：只红 → 只绿 → 只蓝 → 三个都送（白），每 1.5 秒一轮

## 三、已确认的事实（不是推测）

1. **固件确实在芯片里**：用 `STM32_Programmer_CLI -u` 读回 Flash，与编译产物逐字节比对，多次完全一致。
2. **程序确实在运行**：PC13 心跳灯 1Hz 闪烁；改用不同测试图后，屏上内容会发生变化（说明扫描在跑）。
3. **GPIO 配置机制没问题**：心跳灯用的就是同一套 `CRL/CRH` 配置函数，能正常工作。
4. **电源正常**：5V/3A 数控电源，电压稳定。
5. **ST-Link 与下载链路正常**：`Device ID 0x410`、`Cortex-M3`，烧录 0.16~0.26s 完成，复位正常。

## 四、现象记录（按时间顺序）

### 现象 A：最初全黑

电源 0.16A，屏一个像素都不亮。当时固件是"自检：全白→红→绿→蓝→边框→数字3"。

### 现象 B：绿色 8 行 × 32 列（`docs/现象1_绿8行32列_底部蓝.jpg`）

- 第 1~8 行、左半边 32 列亮绿
- 第 64 行、右半边有蓝色
- 电流 0.14A

当时判断为"地址 D/E 没接、R2/G2/B2 没接"——**后来推翻**，见现象 C。

### 现象 C：四色方块测试图（`docs/现象2_四色方块.jpg`）

送出的图是：左上 32×32 = 白，右上 32×32 = 红，左下 32×32 = 绿，右下 32×32 = 蓝。

实拍结果：

- 左上 → **品红/紫**（暗）
- 右上 → **品红/粉**（亮，能看到一颗颗 LED）
- 左下 → **绿**，但只有最下面约 8 行，其余暗
- 右下 → **亮红**

关键：**整屏 64 行 × 64 列都有内容**，不是只亮 8 行。所以"地址线 D/E 缺一根"的判断作废。
但**颜色对应关系明显错位**：我给蓝的位置亮了红，给白的位置亮成品红（缺绿）。

### 现象 D：CLK 放慢 + LAT 加建立时间后（`docs/现象3_竖条纹.jpg`）

改成 `CLK_NOP=8`、`latch()` 前加 8 NOP，目的是排除"CLK 串到 LAT"造成的每列亮度不一致。

实拍结果：

- 变成**完整的竖条纹**：左半偏黄绿、右半偏红、右下偏紫蓝
- 纯色区域**每一列亮度都不一样**（有明暗台阶）
- 四色的大致分布仍在

### 现象 E：单通道轮播（当前固件）

固件每 1.5 秒切换：只红 → 只绿 → 只蓝 → 白。

用户描述：**一直是蓝色的方块，16×16 大小，位置在 (x=32~48, y=1~16) 和 (x=48~64, y=17~32) 之间跳，颜色完全不随轮播变化。**

## 五、已经排除的方向

| 怀疑点 | 排除依据 |
|---|---|
| 固件没烧进去 | 逐字节读回校验一致 |
| 程序没跑 / 卡死 | PC13 心跳灯 1Hz |
| GPIO 配置方式错（F1 的 CRL/CRH） | 心跳灯同套配置可用 |
| 供电不足 | 5V/3A 数控电源，电压稳定 |
| ST-Link / stlinkserver 占用 | 已解决，芯片可正常读写 |
| DWT 延时不可靠 | 已改 SysTick |
| 单纯是 CLK 太快（串扰） | 放慢 4 倍后只是从"色块"变成"竖条纹"，本质未变 |

## 六、当前未确认的可疑点

1. **排线插的是面板的 IN 口还是 OUT 口**（屏背面有两个一模一样的 16P 座），未拍照确认。
2. **第 8 脚（E）是否被误接到 GND**。此前提供给用户的技术文档曾错误地写成"4/8/16 都是地"，用户已指出并修正；但接线是否已经按错误信息接过，未确认。
3. **6 根数据线的实际顺序**是否与表中一致，未逐一核对。
4. **屏 GND 与板子 GND 是否真的连通**（用户口头确认"共地"，未测量）。
5. **3.3V 直接驱动 5V 供电的 74HC245**：Vih 典型值 0.7×VCC = 3.5V，3.3V 处于临界，是否存在"完全识别不了高电平"的可能。
6. **接线方式是散杜邦线**（不是屏自带的 16P 排线），线长约 20cm，无地线回流。

## 七、希望得到解答的具体问题

1. **「屏幕只显示一个 16×16 的色块，且色块位置会变、颜色不随内容变化」这个现象，最可能对应哪一层出了问题？**（数据链路 / 锁存 / 行选 / 缓冲器电平）
2. 如果 74HC245 因 3.3V 电平不足而**完全无法识别**高电平，现象会是什么样？会不会正好是"只有少数像素响应"？
3. HUB75 的 1/32 扫描，行地址 a 是否一定对应「第 a 行 + 第 a+32 行」？有没有厂商用别的映射（例如 a 与 a+16、或按 4 行一组）？
4. 现象 C 里"白色显示成品红（缺绿）、蓝色位置显示红色"，除了接线顺序错，还有没有可能是**位平面数据拼接错误**（例如 bit0~bit5 的映射与我以为的不同）？
5. BCM 位平面方案里，`OE 关 → 移位 64 位 → LAT → OE 开` 这个顺序，有没有可能因为**移位期间 OE 未真正关闭**而出现"每列亮度不同"的竖条纹？
6. 还有没有我没想到的、能解释"内容变了但屏上几乎不变"的机制？
